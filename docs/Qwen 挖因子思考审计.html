这份审计同时使用了本地日志和 Langfuse 云端轨迹。两边结构一致：每轮 1 个 trace，下挂 8 个 observation（检索记忆、生成、解析、评估、更新库、反思、记忆蒸馏、迭代根节点），共 36 个 trace、288 个 observation。Qwen 的思考文本两边都完整保留。

Langfuse 侧有三个可观测性缺口，会直接影响以后的分析：

  • 生成 prompt 没有挂到托管版本。反思调用链接了 factorminer/reflect-on-batch v2，生成调用的 promptName 为空。原因是 resolve_prompt 发现本次特征集（6 个字段，没有 $amt）生成的 system prompt 与默认版本的哈希不同，于是回退到本地 prompt。最关键的 prompt 反而没有版本记录。

3. 思考倾向与偏差

下面 8 条按"从生成到反思"的顺序排列。每条都给出可复核的计数和原文摘录（英文原文保留，附中文意译）。

B1

思考预算花在自我核对上，而不是研究判断

典型的生成思考是：先把整份算子表抄一遍，然后对每个草稿逐个写 "Check … valid. Good."。经济含义通常只有一句 "Economic: …"，没有对方向、量级、适用周期做任何推断。含糊措辞（maybe / could / might）每千词 48.6 次，是经济机制词的 11 倍。

"Check: TsMin($low, 30), TsMax($high, 30) valid. … Div safe. Sign(Delta($volume,7)) valid. Mul valid. CsRank valid. … Economic: price position in 30-day range signed by recent volume change."
逐个核对算子是否合法，经济解释只有一句。it1 · propose-factors · thinking

根因：prompt 把"必须能解析""只能用列出的算子""不要 markdown"写成硬规则并反复强调，却没有一个需要它写出预期方向和理由的输出字段。模型就把注意力放在不会被惩罚的地方。

B2

不知道自己在交易什么

20 万词思考里，S&P / SP500 出现 0 次，"t+1" 0 次，"forward return" 1 次。prompt 从未告诉它：股票池是美国大盘股，标签是 close(t+2)/close(t+1)−1（跳过一天），评估是日频横截面 Rank IC。于是它调用的是"一般意义上的 alpha 教科书"，大量借用 A 股/日内高频语境里才有效的叙事（"informed flow""trapped flow""buying pressure"）。

"Need maybe generate 8 with high chance? Since previous all weak, maybe need more powerful known alphas? With only OHLCV, IC 0.02 hard."
它意识到用 OHLCV 很难到 0.02，但不知道为什么难，也没有可以据此调整的信息。it5 · propose-factors · thinking
B3

正确的先验被框架截断

这是整次运行里最关键的一条证据。模型知道横截面最强的简单因子是 12-1 月动量，但 Return/Delay/Delta/LogReturn 的窗口上限被定为 60，它就把"长期"重新定义成了 60 天，还给它贴上"经典 12-1 动量"的标签。在这份数据上，真正的 12-1 动量 IC 约 0.030，是唯一能过门槛的经典因子；60 日动量只有 0.004。

"Long-term momentum: CsRank(Return($close, 252? but window max 60 for Return, so max 60). Could use Return($close, 60)."
本想写 252 日，因为窗口上限改成 60。it10 · propose-factors · thinking
"CsRank(Sub(Return($close,60), Return($close,10))). This is classic 12-1 momentum. Could be strong."
把 60 日减 10 日当成 12-1 动量。it11 · propose-factors · thinking

在 36 轮里，涉及 120 或 250 日窗口的候选只有 10 个；反思提出的 136 条假设里，只有 3 条提到长周期。

B4

被算子说明误导

system prompt 把 CsNeutralize 描述为 "industry-neutralize"，但数据里没有行业字段，实现只是横截面去均值（对 CsRank 来说等于什么都没做）。模型在思考中 346 次提到 CsNeutralize、238 次提到 industry，反复纠结"没有行业数据它还能不能用"，并把它当成降噪手段。同类问题还有 KAMA（实现是普通 EMA）。

"Maybe use industry-neutralized volume-weighted price location. CsNeutralize instead of CsZScore? Could be stronger if industry removes noise."
以为在做行业中性化，实际上是去均值。it18 · propose-factors · thinking
B5

方向焦虑与"反正测不了"的心态

门槛是 |mean IC|，方向不影响入库，但 prompt 没说，模型在每个草稿上反复犹豫要不要套 Neg（sign / direction 每千词 7.1 次）。同时它清楚自己拿不到任何评估结果，生成逐渐变成"写出看起来合理的东西"。

"Since library empty, any |IC|>=0.02. Hard. We just need plausible. Need not actually test."
只需要"看起来合理"，不需要真的检验。it18 · propose-factors · thinking
"However all 232 candidates failed, best 0.0128. Maybe data regime makes standard factors weak. Need generate plausible but maybe not guarantee. We just output candidates."
它其实猜到了"数据环境让常规因子变弱"，但框架没有任何动作可以去验证这个猜测。it30 · propose-factors · thinking
B6

反思者把噪声讲成因果故事

反思 prompt 要求每条假设说明"为什么既有预测力又与库不相关"。库一直是空的，这个要求变成了模板句。更严重的是 avoid 列表：它基于单个样本、差异小于一个标准误的 |IC|，封杀整个家族，甚至专门禁止"最接近门槛"的方向。

反思输出的特征（34 次成功解析，136 条假设 / 136 条 avoid）条数

假设使用日内/资金流/微观结构叙事92 / 136

avoid 封杀整个家族（动量、波动率、高阶矩、相关、条件、极值）61 / 136

"Avoid plain momentum or delta-based price changes, since five- and fifteen-day momentum variants already produced only |IC| 0.0055."
第 2 轮，仅凭 5 日和 15 日两个样本就禁掉了整个动量家族。it2 · reflect-on-batch · avoid
"Avoid close/open-volume correlation, sign(close-open)*volume, and range-normalized return means, since they were closest but rejected."

根因在于：本次运行的单个候选 IC 标准误约 0.0047，"最接近门槛"的前三名彼此之间、与 0 之间都分不开。框架把这些数字原样交给反思者，却没有给出不确定性。

B7

反思的形式约束在消耗算力，并引发退化

"每条最多 40 个词"让反思思考中 13.4% 的 token 用来逐词计数（形如 "All1 eight2 iteration-2 formulas3 …"）。第 10 和 33 轮的反思跑满 30.8k token 上限（finish_reason=length），各耗时约 587 秒，最终无法解析。第 10 轮是典型的重复退化：同一句话循环了 318 次。

"Could use $high/$low if available? The formulas use $open, $close, $volume, $returns. Maybe $high/$low not guaranteed but likely in alpha library? We can propose using $high and $low? Need maybe avoid if not known."
反思 prompt 不包含可用字段和算子表，模型不确定 $high/$low 是否存在，在这里打转直到 token 用完。it10 · reflect-on-batch · thinking（重复 318 次）
B8

生成器是翻译器，反思者是只有一步记忆的研究总监

对照每轮反思的 4 条假设和下一轮的 8 个公式，生成器几乎逐条照做（例如第 8 轮的 overnight-intraday divergence、return-range intensity、range compression、price-volume slope divergence，第 9 轮原样出现，名字都一样）。真正决定搜索方向的是反思，而反思的输入只有最近一批的结果和家族汇总，看不到自己以前提过的假设、这些假设后来的结果。于是搜索在少数机制间来回转，第 34 轮的输出几乎是第 2 轮的翻版（短期反转、60 日"长动量"、低波、Amihud、K 线位置）。

4. 先验知识是怎么被使用的

把 36 轮的思考连起来读，可以分成四个阶段。

阶段轮次模型在做什么代表因子
A · 教科书采样1–5调出最常见的日频量价因子清单，挑 8 个"多样"的5 日反转、60 日动量、低波、Amihud、偏度、K 线位置
B · 单样本封杀2–8反思用 1–2 个弱样本否定整个家族，avoid 不断累积"Avoid plain momentum…"
C · 微观结构组合6–30教科书被禁后，转向在日 K 线上拼接"资金流/压力"叙事收盘位置 × 量能 z 值、跳空 × 日内强度、上下影线 × 量
D · 回到教科书31–36只看最近一批，忘了早期已测过；重新采样同一份清单第 34 轮 ≈ 第 2 轮

这三张图合起来回答了"有没有足够的发散性"：公式写法是发散的（273/288 不重复），信号层面却大量重复：第 2–36 轮的 280 个候选里，121 个（43%）与更早的某个候选 |ρ|>0.9，相当于换了写法的同一个信号。288 次评估实际只覆盖了约 57 个不同的信号簇，后 24 轮只新增 25 簇。结果层面则完全没有积累。它不是死循环，而是一个没有梯度的随机游走：每一步都"不同"，但没有一步是根据可信证据走的。

为什么先验没有起作用

LLM 的金融先验是"在一般市场里，哪些机制历史上有效"。要让它真正起作用，至少需要三样东西，这次运行都缺：

  1. 情境：市场、股票池、标签周期、样本长度。没有这些，它只能取"平均情境"下的先验，而 SP500 大盘股 + 跳过一天的标签恰好是短周期量价因子最弱的情境。
  2. 表达能力：先验指向的因子要能写出来。窗口上限 60 让最强的那条先验（12-1 动量）写不出来，加上除法 bug，长窗口的写法还会被稀释 1/3。
  3. 可信的反馈：先验需要被数据确认或否定。反馈低于噪声底时，"否定"本身就是噪声，反思把它当成事实，最终把正确的先验也封杀了。

6. 框架改进建议

建议的核心思路是：把 LLM 从"凭感觉生成并过滤公式"的位置挪到"提出可证伪的假设、解释可信的证据"的位置，把大规模枚举和统计判断交给便宜的程序。下面按你关心的三个方向组织，最后给一个整体架构和落地顺序。

6.1 先让反馈变得可学习（这是其他一切的前提）

  • 每个候选都报告不确定性。给出 mean IC、标准误、t 值和 block bootstrap 置信区间；标出"显著为正/负""与 0 分不开"三种状态。反馈里"最接近门槛"只列显著的，不显著的统一写成"未能区分于 0"，不给排序。
  • 把筛选和入库分开。入库门槛可以保持严格，但给反思看的应该是"这个方向有没有信号"：例如对同一假设下的一组变体做 FDR 控制后的检验，或看变体 IC 分布是否整体偏离 0。
  • 在 prompt 里写明情境。市场、股票池、频率、标签公式、训练期长度、预热期处理、"门槛用 |IC|，方向无所谓"。这几行字的成本几乎为零。
  • 先跑基线做标定。每次新数据集，先自动评估一组固定的经典因子（Alpha158 / 动量 / 反转 / 低波 / 规模），把结果作为"这个数据集上什么有效"的先验证据放进第一轮 prompt。本次如果有这一步，第 1 轮就会知道只有长周期动量有效。
  • 门槛按数据集自动标定。例如以随机公式 IC 分布的 99 分位或基线因子的分位数为准，避免在一个"物理上不可能"的门槛下空转 36 轮。

6.2 搜索更广阔的空间

  • LLM 出"假设 + 骨架"，程序做枚举。让 LLM 输出结构化假设：机制、预期方向、适用周期、骨架公式（窗口、阈值等留作参数槽）。程序对每个骨架做网格枚举（窗口 5/10/20/60/120/250，平滑与否，rank/zscore），一次评估几十到上百个变体。评估 1 秒一个，这比 LLM 多想 1 万个 token 便宜得多。
  • 放开窗口上限并显式覆盖周期。Delay/Return 至少放到 252；把"周期"作为一个独立维度（日内/1 周/1 月/1 季/1 年），每轮强制每个周期桶至少有 1 个候选。
  • 按"机制 × 周期 × 数据字段"建覆盖网格。用多臂老虎机（如 Thompson sampling）在格子之间分配评估预算：没测过的格子有探索奖励，测过且显著的格子做局部精修，测过且确定无效的格子降权但不永久封禁。
  • 把 LLM 的草稿全部交给评估。思考里已经写出约 78 个草稿，直接解析出来去重后全部评估，比让 LLM 凭感觉挑 8 个更有信息量。
  • 加入局部变异。对显著的候选做程序化变异（换窗口、换字段、加条件），类似遗传编程，LLM 只负责解释哪些变异方向有经济意义。

6.3 更高效地利用记忆

把现在的"上一批反馈 + 家族汇总"换成一个结构化的假设账本。每条假设一行，生成和反思都必须引用账本里的 ID。

字段例子用途

  • 评估前查重。先按规范化公式哈希查，再按信号相关性查（与历史某候选 ρ>0.95 视为重复），命中就直接返回历史结果，并在反馈里说明"这是第 N 次测试"。
  • 检索按机制而不是按算子。家族分类改为机制 × 周期 × 字段；每族保留的不只是最好 2 例，而是"已测邻域摘要"（窗口范围、变体数、结论）。
  • 反思必须读账本。反思的输入里加上它以前提出的假设和各自的检验结果，输出必须标明每条新假设是"新开""精修 H-xxx"还是"重开 H-xxx"。
  • 思考里的推理留档。允许生成输出一个简短的 rationale 字段（机制、预期方向、预期周期），写进账本，这样事后才能判断"假设被证伪"还是"实现写错"。

6.4 减少偏见，别被自己的反馈带偏

  • avoid 必须有统计依据。只有当一组变体整体显著无效（例如 CI 上界 < 0.005 且变体数 ≥ 10）时才允许封禁；单样本、与 0 分不开的结果只能标为"证据不足"。封禁要带范围和到期轮次。
  • 每批混入对照。每批固定加 1–2 个随机公式和 1 个已知基线，用来实时标定噪声底；如果 LLM 候选的 |IC| 分布和随机公式分不开，系统应该直接提示"当前方向没有信息"，而不是让反思继续讲故事。
  • 反思和生成角色分离，并引入反方。一个角色负责从账本里找"被过早否定的方向"，一个负责找"可能是噪声的正面结果"。两者分歧时以统计检验为准。
  • 强制探索配额。例如每批 8 个里，至少 2 个来自未覆盖的格子、至少 2 个是账本里"证据不足"假设的重测。
  • 别让话术替系统做决定。删除 feedback.py 里"窗口调整很少有用""三轮没入库就换方向"这类固定话术，改成根据数据生成的诊断（例如"同一机制下窗口 20→250 的 IC 单调上升"）。
  • 对 holdout 保持盲。挖掘全程不看 2026 年数据；累计尝试次数纳入最终检验（deflated Sharpe 或 FDR），避免"试得越多越容易撞到假阳性"。

6.5 工程与可观测性

  • P0修复 _safe_div 的 NaN 传播；常数截面的 IC 记为 NaN 而不是 0；CsRank 并列值用平均秩。
  • P0Delay/Return/Delta 窗口上限放到 252；修正 CsNeutralize、KAMA 的说明（或实现真正的行业中性化）。
  • P1反思 prompt 带上字段和算子表；去掉 40 词上限，改为结构化 JSON 字段长度限制；加重复检测，发现循环立即截断重试；反思 max_tokens 设到 8k 左右。
  • P1生成 prompt 改为模板化（特征表作为变量），让它能挂上 Langfuse 托管版本；每个候选的 IC、t 值、outcome 作为 score 写回 trace；设置 completionStartTime。
  • P2限制生成阶段的思考预算（或改用非推理模式生成骨架、推理模式只用于反思），把省下的时间换成评估。

7. 怎么验证改进有效

"挖出一个因子"不是好的验收标准，它会鼓励放宽门槛或在同一份数据上多试。建议用下面四个指标对比改动前后，同一数据、同一预算：

  1. 相对随机基线的命中率：LLM 候选中显著（FDR 后）的比例，减去同等数量随机公式的比例。这次运行这个差值约为 0。
  2. 每次评估的信息增益：覆盖格子数、账本里"支持/证伪"状态的假设数，随评估次数的增长曲线。
  3. 信号新颖度：每轮新候选与历史候选最大相关系数的分布，看是否持续有低相关的新信号。
  4. 样本外稳定性：只在最终阶段使用 2026 holdout，考察入库因子 IC 的衰减，并对累计尝试次数做多重检验校正。
